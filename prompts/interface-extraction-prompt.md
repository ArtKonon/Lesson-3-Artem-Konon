## Мій промпт

Ти — Go-розробник. Мені потрібно зробити рефакторинг та покрити тестами Go-пакет `orders`.

Ось вихідні вимоги та код:

1. Архітектурні вимоги:
   - Дотримуйся приказки Роба Пайка: "чим більший інтерфейс, тим слабша абстракція". 
   - Виокреми мінімальний інтерфейс `OrderStore`, який містить лише необхідний для роботи метод `Exec(query string, args ...any) error`.
   - Використай Впровадження залежностей (Dependency Injection) через конструктор `NewOrderService(store OrderStore)`.

2. Реалізація методу:
   - Реалізуй метод `PlaceOrder(orderID string, amount float64) error` у структурі `OrderService`.
   - Метод повинен викликати `s.store.Exec(...)` із SQL-запитом "INSERT INTO orders (id, amount) VALUES (?, ?)" та відповідними аргументами.
   - Поверни помилку, якщо `Exec` зазнав невдачі, або `nil` у разі успіху.

3. Тестування (без реальної БД):
   - Згенеруй окремий тестовий файл `orders_ai_test.go`.
   - Створи мок-структуру `MockStore`, яка реалізує інтерфейс `OrderStore`.
   - Напиши unit-тести для `PlaceOrder`, які перевіряють:
     a) Успішне створення замовлення (мок повертає nil).
     b) Обробку помилки бази даних (мок повертає error).

Будь ласка, надай повністю готовий код для файлів `orders.go` та `orders_ai_test.go`.
